## 🎯 Что это за проект?

**MineBridge** — это полнофункциональный Telegram-бот для поиска и скачивания модов, шейдеров и ресурспаков Minecraft. Проект состоит из двух компонентов:

1. **Telegram Bot** — основной бот для взаимодействия с пользователями
2. **Next.js Website** — веб-сайт для поиска модов

---

## 🏗️ Архитектура в двух словах

```
Пользователь (Telegram)
    ↓
Telegram API (Webhook)
    ↓
Vercel Serverless (api/webhook.ts)
    ↓
Bot Logic (src/bot.ts)
    ↓
API Clients (Modrinth, CurseForge)
    ↓
Supabase (PostgreSQL)
```

## 🔑 Основные компоненты

### 1. Telegram Bot (src/bot.ts)

**Что делает:**
- Обработка команд (/start, /mybot, /mystats, /channel)
- Поиск модов/шейдеров/ресурспаков
- Фильтрация по версии и загрузчику
- Скачивание файлов
- Рассылка новостей
- Админ-панель со статистикой

**Ключевые функции:**
```typescript
- Управление состоянием пользователей (Map)
- Rate limiting (3 запроса/минуту)
- Логирование в Supabase
- Inline режим для поиска
- Пагинация результатов
```

### 2. API Клиенты

**Modrinth API (src/api/modrinth.ts)**
- Поиск модов/шейдеров/ресурспаков
- Получение версий
- Без API ключа

**CurseForge API (src/api/curseforge.ts)**
- Поиск модов
- Получение файлов
- Требует API ключ

### 3. База данных (Supabase)

**Таблицы:**
- `user_requests` — логирование запросов
- `search_history` — история поиска
- `download_stats` — статистика скачиваний
- `user_bots` — пользовательские боты

### 4. Next.js Website

**API Routes:**
- `/api/search` — поиск модов
- `/api/item/[itemId]` — детали мода
- `/api/versions/[itemId]` — версии мода

**Компоненты:**
- SearchBar, ContentGrid, FilterPanel
- ContentCard, VersionSelector
- SkeletonGrid для загрузки

## 🚀 Как это работает?

### Сценарий: Поиск мода

```
1. Пользователь: /start
2. Бот: Главное меню
3. Пользователь: Нажимает "🔧 Моды"
4. Бот: Проверка rate limit → Запрос версии
5. Пользователь: Выбирает версию (1.20.1)
6. Бот: Запрос загрузчика
7. Пользователь: Выбирает Forge
8. Бот: Запрос названия мода
9. Пользователь: Вводит "JEI"
10. Бот: Поиск в Modrinth API
11. Бот: Фильтрация по версии/загрузчику
12. Бот: Отправка результатов
13. Пользователь: Выбирает мод
14. Бот: Загрузка версий
15. Пользователь: Выбирает версию
16. Бот: Проверка размера файла
17. Если < 50 МБ: Скачивание и отправка
    Если > 50 МБ: Отправка прямой ссылки
```

## 🔄 Жизненный цикл запроса

```
1. Telegram отправляет update
2. Vercel получает POST /api/webhook
3. api/webhook.ts обрабатывает
4. bot.handleUpdate(req.body)
5. Telegraf маршрутизирует
6. Handler выполняется
7. Взаимодействие с API/БД
8. Отправка ответа пользователю
9. Возврат 200 OK в Telegram
10. Serverless функция завершается

Всего: ~1-3 сек
```
